Project report

About the project

Tourist Place Reviews Sentiment Classification Using Machine Learning — B.Tech CSE (AI & ML) interdisciplinary project.

Abstract

Tourist reviews carry first-hand information about what visitors think of a destination, but travellers write in many languages and reading thousands of reviews by hand is slow and inconsistent. This project classifies a review written in any of 16 supported languages as positive, negative or neutral. It uses a pretrained multilingual transformer (XLM-RoBERTa, fine-tuned by clapAI on the 3.9-million-review MultiLingualSentiment dataset) for inference, with automatic language detection. Performance is measured on held-out samples and reported per class and per language.

Problem statement

Thousands of new reviews are posted about tourist destinations every day. Star ratings alone do not explain why a visitor was happy or unhappy, and reading every review manually does not scale.

  • Manual reading is too slow for the volume of text.
  • A rating hides the reason behind it.
  • Different readers judge the same review differently.
  • Recurring complaints and trends are missed.

Objectives

  • Automate the reading of large volumes of tourist reviews.
  • Classify each review as positive, negative or neutral, in any supported language.
  • Use a pretrained multilingual transformer instead of language-specific rules.
  • Measure accuracy, macro/weighted F1 and per-language performance honestly.
  • Give tourists and tourism organisations data-backed insight.
  • Keep the application understandable and easy to extend.

Existing system & limitations

  • Manual review reading – slow, expensive, impossible to scale.
  • Star-rating summaries – average scores hide the actual reasons.
  • Simple keyword matching – misjudges sarcasm, negation and mixed opinions.
  • No trend tracking – rarely shows how sentiment changes over time.

Proposed system & advantages

  • Fully automated classification by trained ML models.
  • Multilingual – one model handles 16 languages without translating reviews first, so the original text is preserved.
  • Context-aware – a transformer reads whole sentences, so negation and word order are captured.
  • Fast and scalable – thousands of reviews in seconds.
  • Measurable – results are comparable through standard metrics.

Machine learning algorithms

Algorithms in this project

Used by the website · inference

Multilingual transformer: XLM-RoBERTa-base (clapAI fine-tune)

A pretrained transformer (278M parameters) that represents text as subword tokens and learns context with self-attention. clapAI fine-tuned it on the train split of the MultiLingualSentiment dataset to output positive / negative / neutral. This project downloads the published model and runs it; it does not train or fine-tune a model on your laptop. A lighter alternative, mmBERT-small (140M parameters), can be selected with one environment variable.

Classical background · optional baseline

Multinomial Naive Bayes

Probabilistic classifier assuming words are independent given the class. Fast, but it works on word counts, so it has no notion of meaning across languages.

Classical background · optional baseline

Support Vector Machine (SVM)

Finds the maximum-margin separating hyperplane; strong on sparse TF-IDF features of a single language, but a model trained on one language cannot classify another.

Classical background · optional baseline

Random Forest

An ensemble of decision trees combined by voting. Robust, but like the other classical models it needs language-specific text features.

Discussed, not implemented

LSTM / BiLSTM

Recurrent sequence models that read words in order (BiLSTM in both directions). They are part of the project’s literature survey; this website does not include or run an LSTM/BiLSTM model. Transformers have largely replaced them for multilingual text.

The literature survey in the project report cites Wadhe & Suratkar (2020), who found TF-IDF with Random Forest gave the best accuracy (86%) among the traditional methods they tested. That figure is from the literature, not from this system — this system’s own results are on the Dashboard.

Feature extraction

Count Vectorizer, TF-IDF and subword tokens

Count Vectorizer (Bag of Words)

Builds a vocabulary of all words and represents each review as a vector of word counts. Simple, but very common words (“the”, “place”) get large values even though they say little about sentiment.

TF-IDF

Re-weights each word by how informative it is: frequent in this review, rare across all reviews. Used by the classical baselines; not by the live multilingual model.

TF-IDF(t,d) = TF(t,d) × IDF(t)
IDF(t) = log( N / df(t) )  (scikit-learn uses a smoothed variant)

Subword tokenization (what the live model uses)

The transformer splits text into subword pieces from one shared multilingual vocabulary (for example, an unfamiliar word becomes a few known fragments). This works for languages without spaces such as Chinese and Japanese, where Count/TF-IDF word features break down. Each token is then turned into a context-aware vector by the network.

How the evaluation avoids leakage

The published model was fine-tuned by its authors on the train split. Here, candidate models are compared on a validation sample and the chosen model is reported once on a test sample. Exact-duplicate texts are removed from every evaluation sample, and an optional check counts evaluation texts that also occur in the training split. Metrics use macro F1 and balanced accuracy so the smaller Neutral class is not hidden, and are broken down per class, language and domain.

Limitations

  • Not tourism-only data. The dataset mixes product, movie, app, tweet, bank and travel reviews; only some domains (e.g. hotel, restaurant, places) are tourist-like. Use the domain filter in evaluate_model.py to measure those.
  • Label noise. Labels come from aggregated third-party datasets; the public preview shows at least one clearly negative hotel review labelled positive, so scores are bounded by label quality.
  • Low-resource languages. According to the dataset card, Hindi (~9.4k), Malay (~6.7k) and Italian (~3.0k) have far fewer records than English (~1.5M) or Chinese (~445k), so the model is likely less reliable there and our evaluation samples for them may be small.
  • Other languages. Languages outside the 16 are not translated; they are still scored but flagged as unsupported.
  • Short text. Automatic language detection is unreliable for very short reviews; choose the language manually.
  • Neutral is inherently the most ambiguous class.
